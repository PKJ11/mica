    Market Basket Analysis

    Which products do customers buy together? Market Basket Analysis answers this question using sales bills. In this module we start with a few bills from Dhanvanshi Super Store, learn the three key measures (Support, Confidence and Lift), study the Apriori algorithm, and then solve ten business problems step by step.

    Learning outcomes

    After completing this module, you will be able to:

    • Calculate Support, Confidence and Lift by hand and explain what each measure tells a manager.
    • Identify rules that look strong on confidence but are no better than chance.
    • Run the Apriori algorithm by hand, including candidate generation and pruning.
    • Convert association rules into business decisions such as shelf placement, combo offers, product bundles, recommendations and cross-selling.

    Where is it used?

    The idea of a "basket" is not limited to a shopping trolley. Any set of things that occur together can be treated as a basket. Some examples are the items in a grocery bill, the dishes in a food delivery order, the books in an online cart, the products held by a bank customer, and the pages visited in one browsing session.

    Chapter 1

    Transactions and itemsets

    Before we measure anything, let us fix the terms we will use throughout this module.

    Basic terms

    • Item set of the store I = {i1, i2, …, id}: all the products the store sells. For Dhanvanshi Super Store, d = 5.
    • Transaction T ⊆ I: the set of items in one bill. Our dataset D has N = 10 transactions.
    • Itemset X ⊆ I: any group of items. An itemset with k items is called a k-itemset. For example, {Bread, Butter} is a 2-itemset.
    • Support count σ(X): the number of transactions that contain every item of X.

    Ten bills from Dhanvanshi Super Store

    The same data as a binary matrix

    Algorithms do not read bills directly. They read a table with one row for each transaction and one column for each item. A cell has 1 if the item is present in that bill and 0 if it is not. Move your cursor over a row to see the matching bill above.

    Note

    Market Basket Analysis records only whether an item is present in a bill. Buying one packet of bread or five packets looks the same, and the price is not used. Support, Confidence and Lift are all calculated on this 0/1 table.

    How many itemsets are possible?

    Each item is either in an itemset or not in it. So d items give 2d − 1 non-empty itemsets. This number grows very fast as the number of items increases. This is the reason we need a smart method like the Apriori algorithm.

    Chapter 2

    Support

    Support answers the first business question: how common is this combination of items?

    Support of an itemset Support(X) = σ(X)N     and for a rule   Support(X → Y) = σ(X ∪ Y)N

    Support is a fraction between 0 and 1. It is the probability that a randomly selected bill contains all the items of X, i.e. Support(X) = P(X).

    Common mistake: ∪ means "all of them", not "either"

    σ(X ∪ Y) counts bills that contain every item of X and every item of Y. Many students wrongly count the bills that have Bread or Butter.

    Support calculator

    Select one or more items. The bills that contain the complete itemset are highlighted in yellow.

    Minimum support (minsup)

    We keep only those itemsets whose support is at least a chosen value called minimum support. Such itemsets are called frequent itemsets. The threshold helps in two ways: it removes combinations that are too rare to act upon, and it reduces the amount of computation.

    • If minsup is too high, you only find the obvious best-selling items and miss smaller but profitable combinations.
    • If minsup is too low, you get thousands of itemsets, many of which appear in only a handful of bills by chance.
    • A large supermarket with thousands of products usually uses a minsup well below 1%, because any one item appears in only a small share of bills. For our small dataset of ten bills we use 30%, i.e. 3 bills.
    Practice: find the support of {Bread, Butter, Milk}

    Bills 01, 04 and 08 contain all three items. So Support = 3/10 = 0.30. This is exactly equal to minsup = 30%, so the itemset is frequent.

    Chapter 3

    Confidence

    Confidence answers the question: out of the bills that contain X, what fraction also contain Y?

    Confidence of the rule X → Y Confidence(X → Y) = σ(X ∪ Y)σ(X) = Support(X ∪ Y)Support(X) = P(Y | X)

    Confidence is a conditional probability. The denominator is no longer all bills (N); it is only the bills that contain the antecedent X. It tells us how reliable the rule is whenever X is present.

    Confidence calculator

    Blue bills contain X only. Yellow bills contain both X and Y. Confidence = yellow bills ÷ (blue + yellow bills). An item selected in X cannot be selected in Y.

    Direction matters

    Interchange X and Y in the calculator and see how the answer changes. Confidence(Bread → Butter) = 5/7 = 0.71, but Confidence(Butter → Bread) = 5/5 = 1.00, i.e. every customer who bought butter also bought bread. The numerator is the same in both cases; only the denominator changes. For a manager, "suggest butter to bread buyers" and "suggest bread to butter buyers" are two different decisions.

    Limitation of confidence

    Set the calculator to Bread → Milk. Confidence is 0.71, which looks high. But 7 of the 10 bills contain milk anyway, so 0.71 is hardly more than what we would expect from any bill. Confidence does not consider how popular the consequent already is. Lift takes care of this.

    Practice: find Confidence(Milk → Eggs) and Confidence(Eggs → Milk)

    σ(Milk, Eggs) = 3, σ(Milk) = 7 and σ(Eggs) = 4. So Confidence(Milk → Eggs) = 3/7 = 0.43 and Confidence(Eggs → Milk) = 3/4 = 0.75.

    Chapter 4

    Lift

    Lift answers the question: when X is in the bill, how many times more likely is Y compared with any bill?

    Lift of the rule X → Y Lift(X → Y) = Confidence(X → Y)Support(Y) = Support(X ∪ Y)Support(X) × Support(Y)

    From probability we know that if X and Y are independent, then Support(X ∪ Y) = Support(X) × Support(Y). Lift compares what actually happened with what independence would give.

    LiftMeaningTypical action
    > 1Positive association: X makes Y more likelyKeep together, bundle, recommend
    = 1Independent: X tells us nothing about YIgnore the rule, even if confidence is high
    < 1Negative association: X makes Y less likely (often substitute products)Do not bundle; check for substitution

    Lift is symmetric: Lift(X → Y) = Lift(Y → X), because the second form of the formula does not depend on which item is on which side. So lift tells us whether an association exists, and confidence tells us which direction is more useful.

    Lift calculator

    Be careful with rare itemsets

    Suppose two items each appear in 2 out of 10,000 bills and appear together in just one bill. The lift works out to 2,500, but one bill is not a pattern. Always read lift together with support.

    Practice: find the lift of Tea → Bread

    σ(Tea, Bread) = 1 (Bill 07) and σ(Tea) = 3, so Confidence = 1/3 = 0.33. Support(Bread) = 0.70, so Lift = 0.33 / 0.70 = 0.48. Customers who buy tea are less than half as likely as an average customer to buy bread.

    Chapter 5

    Association rules

    An association rule converts a frequent itemset into a statement that a manager can act upon.

    Association rule X → Y,   where X, Y ⊆ I and X ∩ Y = ∅

    X is called the antecedent (left-hand side, the "if" part) and Y is called the consequent (right-hand side, the "then" part). A rule is called strong when Support(X → Y) ≥ minsup and Confidence(X → Y) ≥ minconf. In practice we also check that Lift > 1, because a strong rule can still be independent.

    Rule mining is done in two steps

    1. Frequent itemset generation: find all itemsets with support ≥ minsup. This step needs the most computation.
    2. Rule generation: split every frequent itemset into antecedent and consequent in all possible ways, and keep the rules with confidence ≥ minconf. No fresh scan of the data is needed here, because all the support values are already known from step 1.

    Why checking every rule is not practical

    With d items, the total number of possible rules is

    Number of possible rulesR = 3d − 2d+1 + 1

    Each item can go to the left side, the right side, or neither side, which gives 3d arrangements. From these we remove the arrangements where either side is empty.

    A shortcut during rule generation

    For rules made from the same itemset, moving items from the antecedent to the consequent can never increase confidence, because the denominator Support(X) can only become larger when X becomes smaller. So Confidence(Butter, Milk → Bread) ≥ Confidence(Butter → Bread, Milk). If a rule fails minconf, every rule with a smaller antecedent taken from it will also fail.

    Association is not causation

    The rule Bread → Butter does not mean that buying bread causes a customer to buy butter. Both may be driven by a third reason, such as shopping for breakfast. Treat every rule as a hypothesis and test the business action (for example, a trial shelf placement or a trial combo) before applying it across all stores.

    Chapter 6

    The Apriori algorithm

    The Apriori algorithm (Agrawal and Srikant, 1994) finds all frequent itemsets without checking all 2d of them. It is based on one simple property.

    The Apriori property (downward closure) If an itemset is frequent, all of its subsets are also frequent. Equivalently, if an itemset is infrequent, all of its supersets are also infrequent.

    Reason: if X ⊆ Y, every bill that contains Y also contains X. So σ(X) ≥ σ(Y). Support can only decrease as we add items. This property is called anti-monotonicity, and it allows Apriori to reject a candidate without even counting it.

    Steps of the algorithm

    1. Scan the data and count every single item. Keep the items with count ≥ minsup. This set is L1.
    2. Join: form candidate k-itemsets Ck by combining pairs of frequent (k−1)-itemsets whose union has exactly k items.
    3. Prune: remove every candidate that has an infrequent (k−1)-subset. By the Apriori property, such a candidate can never be frequent.
    4. Count: scan the data again and count the remaining candidates. Keep those with count ≥ minsup. This set is Lk.
    5. Repeat with k + 1 until no new frequent itemsets are found.
    6. Generate rules from all frequent itemsets and keep those with confidence ≥ minconf.
    Apriori(D, minsup):
    L1 ← frequent 1-itemsets
    k  ← 2
    while L(k-1) is not empty:
        Ck ← { a ∪ b : a, b in L(k-1), |a ∪ b| = k }        # join
        Ck ← { c in Ck : every (k-1)-subset of c is in L(k-1) }  # prune
        count every c in Ck with one pass over D                   # scan
        Lk ← { c in Ck : count(c) ≥ minsup }
        k  ← k + 1
    return L1 ∪ L2 ∪ …

    Many textbooks join only those itemsets that have the same first k−2 items (after sorting). This gives fewer candidates. The method shown above is easier to follow by hand and gives exactly the same frequent itemsets.

    Go through the algorithm one step at a time on our ten bills. Change the minimum support and observe which candidates become frequent, which fail the count, and which get pruned without counting.

    Limitations of Apriori

    Apriori needs one complete scan of the data for every level, and with a low minsup the number of candidates in C2 alone can run into lakhs. Two well-known algorithms reduce this effort. FP-Growth stores the data in a compact prefix tree (FP-tree) using only two scans and finds frequent itemsets without generating candidates. Eclat stores, for every itemset, the list of transaction IDs in which it appears, and finds support by intersecting these lists. All three algorithms give the same frequent itemsets; they differ in speed and memory usage.

    Apriori in Python and R

    On real data, Apriori is run using a library. In Python, the mlxtend library takes a one-hot table like the binary matrix in Chapter 1:

    from mlxtend.frequent_patterns import apriori, association_rules

freq  = apriori(onehot_df, min_support=0.3, use_colnames=True)
rules = association_rules(freq, metric="confidence", min_threshold=0.7)
rules.sort_values("lift", ascending=False)

    In R, the arules package does the same: apriori(trans, parameter = list(supp = 0.3, conf = 0.7)).

    How to read a rule

    1. Is the support high enough to matter for the business?
    2. Is the confidence high enough to act upon in this direction?
    3. Is the lift clearly above 1? If not, drop the rule.
    4. Which direction has higher confidence? Use that direction.

    Apriori in short

    Count single items and keep the frequent ones. Join frequent (k−1)-itemsets to form k-item candidates, prune candidates that have an infrequent subset, count the rest and keep the frequent ones. Repeat until no frequent itemset is left. Then split each frequent itemset into rules and keep those above minconf.

    Points to remember

    • High confidence but lift close to 1: the consequent is simply a popular item (Bread → Milk; Veg puff → Masala chai at FoodJoe).
    • Very high lift but very low support: most likely a chance occurrence in a few bills.
    • Lift does not show direction: lift is the same both ways, so use confidence to choose the direction.
    • Daily-use staples: items present in most bills pass every threshold but give little insight. Remove them or analyse each category separately.
    • Association is not causation: test the action before applying it everywhere.
    • σ(X ∪ Y) means "and": count only bills that contain all items of both sides.

    Useful counts

    • Non-empty itemsets from d items: 2d − 1
    • Possible rules from d items: 3d − 2d+1 + 1
    • Rules from one frequent k-itemset: 2k − 2
