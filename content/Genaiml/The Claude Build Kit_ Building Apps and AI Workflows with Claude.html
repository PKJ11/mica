    Round 1 of 8

    Building an app is a loop, not one prompt

    The idea

    You can build a working app with plain English, but not in one giant prompt. Good builders run a loop: specify what they want, ask Claude for a plan, build one small slice, test it, then refine it before moving to the next slice.

    Small slices keep mistakes small. A bug found in one screen takes one message to fix. A bug buried in a whole app built in one go can take an hour.

    Round 2 of 8

    Take a strong prompt apart

    The idea

    Write to Claude the way you’d brief a smart new colleague on their first day. They need the context, a clear goal, who it’s for, the must-have requirements, the limits, an example of good work, the format you want back, and how you’ll judge it.

    Three habits make any prompt better. Say what to do, rather than what not to do. Give the reason behind a rule, because Claude uses the reason to handle cases you didn’t mention. And wrap long pasted material in tags, such as <reviews> … </reviews>, so Claude can tell your instructions apart from your material.

    Round 3 of 8

    CLAUDE.md: your project’s standing brief

    The idea

    Every new Claude Code session starts with a blank memory. CLAUDE.md is a plain-text file in your project folder that Claude reads at the start of every session, so it always knows what the project is, how you work and which rules to follow.

    You don’t have to write it from scratch. Run /init and Claude explores the project and drafts one for you to review. Because the file loads every session, every line costs tokens every time: aim for under 200 lines, and add a line when you catch yourself explaining the same thing twice. On claude.ai, the instructions and files of a Project play the same role.

    Round 4 of 8

    Skills: teach Claude a task once

    The idea

    A Skill is a folder that teaches Claude how to do one repeatable task well, such as writing a research summary in your format. At its heart is a file called SKILL.md: a name and a short description at the top, then the instructions. Examples, templates and small scripts can sit in the same folder.

    Claude reads only the name and description of each Skill until a task matches. Then it opens the instructions, and opens the extra files only if it needs them. That’s why you can install dozens of Skills without slowing Claude down. Skills work on claude.ai, in Claude Code and through the API, and you can ask Claude to create one for you.

    Round 5 of 8

    Brand files and Claude Design

    The idea

    A BRAND.md file is your brand guide rewritten for Claude: exact values, not adjectives. “Warm and premium” means nothing to a machine. “Buttons in #B61D22, square corners, sentence case” does. To make one, give Claude your logo, brand guide and a few screenshots, ask it to draft a BRAND.md with exact values, then correct what it got wrong.

    BRAND.md isn’t a name Claude looks for on its own, so point to it: from CLAUDE.md, from your Project files, or in your prompt.

    Part B. Designing in Claude Design

    The idea

    Claude Design is Anthropic’s visual workspace for designs, app screens, prototypes, slides and one-pagers. You can start it from claude.ai/design or from a conversation. Import your design system, from brand files, design files or a code repository, and Claude builds with it and checks its own output against it.

    You refine by commenting on the exact element you want changed. When the design is right, you can export it or hand it to Claude Code to build. Designing first is cheap: changing a picture costs far less than changing a finished app.

    Round 6 of 8

    CHECKS.md and a testing agent

    The idea

    A CHECKS.md file lists what every output must pass before you accept it, written as yes-or-no checks. You can ask Claude to run it on its own work: “Before you show me anything, check it against CHECKS.md and report pass or fail for each line.” A good check is specific, observable, and has only one right answer.

    Part B. Build a testing agent

    The idea

    A testing agent is a separate agent whose only job is to check work against CHECKS.md. This is the maker-and-checker pattern from The AI Spectrum: a reviewer that didn’t build the work doesn’t share the builder’s blind spots.

    In Claude Code, you create one with the /agents command. It’s saved as a file in the project’s .claude/agents folder, with a name, a description of when to use it, the tools it may use, and its instructions. On claude.ai, the same idea is a separate chat or Project set up with checker instructions.

    Round 7 of 8

    Refine before you build, and save tokens

    The idea

    Tokens are the small chunks of text Claude reads and writes, and your usage is counted in them. Every message you send makes Claude re-read the conversation so far, plus the files and instructions it has loaded. So long chats, pasted documents and regenerated files add up quickly.

    The biggest saving comes before any building. A plan is short; an app is long. Fixing a misunderstanding in a one-page SPEC.md costs a few hundred tokens. Fixing the same misunderstanding after the app is built can mean rewriting thousands. So write the spec, ask Claude to critique it and question you, correct it, and only then build.

    Round 8 of 8

    Put the kit together

    The idea

    Each instruction has a right home. Say it in the right place once, and you never have to repeat it. A prompt is for this task. SPEC.md is for this build. CLAUDE.md is for every session in the project. BRAND.md is for how things look and sound. CHECKS.md is for what every output must pass. A Skill is for a process you’ll repeat anywhere.

    Part B. Final design calls

    Debrief

    What you now know

    1. Building with prompts is a loop. Specify, plan, build one slice, test, refine, then move to the next slice.
    2. A strong prompt is a brief. Context, goal, audience, requirements, constraints, an example, output format and success criteria. Say what to do, give reasons, and tag pasted material.
    3. CLAUDE.md is the project’s standing brief. Claude reads it every session. Draft it with /init, keep it under 200 lines, and add to it when you repeat yourself.
    4. A Skill teaches Claude a repeatable task. A SKILL.md with a clear name and description, instructions, and optional examples and scripts, loaded only when needed.
    5. BRAND.md turns adjectives into values. Exact colours, fonts, shapes and voice rules that Claude can follow and check.
    6. Claude Design lets you get the look right before you build. Import your design system, comment on exact elements, explore alternatives, then hand off to build.
    7. CHECKS.md makes quality testable. Specific yes-or-no checks that Claude can run on its own work.
    8. A testing agent is your checker. A separate agent with read-only tools that reports pass or fail with evidence, and never marks its own homework.
    9. Refine the plan, not the product. Fixing SPEC.md costs hundreds of tokens; fixing a built app costs thousands.
    10. Save tokens by design. Batch feedback, ask for targeted edits, start fresh chats for new tasks, keep standing files lean, and match the model to the job.

    • Draft BRAND.md and CHECKS.md for your project. Make every line specific enough to pass or fail.
